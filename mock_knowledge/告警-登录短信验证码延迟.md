# 登录短信验证码延迟告警处理手册

## 告警名称

SMS-OTP-LATENCY-HIGH

## 适用范围

适用于登录、注册、找回密码、支付二次验证等短信验证码发送延迟或失败率升高的场景。

## 告警触发条件

- 指标：`sms_send_duration_seconds_bucket`、`sms_send_failure_total`
- 触发：P95 延迟大于 8 秒，或失败率大于 5%，持续 5 分钟
- 严重级别：P2；如果登录转化明显下降，升级 P1

## 首要确认

1. 区分是所有运营商异常，还是某个运营商或地区异常。
2. 查看短信供应商返回码是否集中为限流、签名错误、模板未审核。
3. 查看验证码服务队列是否积压。
4. 查看是否有异常刷短信流量触发风控。

## 排查命令

```bash
kubectl -n prod logs deploy/otp-service --since=20m | grep -E "sms_provider|rate_limit|template|carrier"
redis-cli -h redis-prod llen otp:sms:queue
curl -s http://otp-service:8000/metrics | grep sms_send
```

## 常见原因

- 主短信供应商接口限流或局部不可用。
- 新短信模板未审核通过。
- 短信签名配置被误改。
- 验证码发送队列消费者异常退出。
- 攻击流量导致手机号或 IP 维度风控拦截。

## 处置步骤

1. 如果主供应商失败率超过 5%，将短信路由切换到备用供应商。
2. 如果模板未审核，通过配置中心回滚到上一可用模板 ID。
3. 如果队列积压，扩容 `otp-sms-worker`，并限制单用户重发频率。
4. 如果疑似攻击，启用图形验证码或滑块验证，并提高 IP 维度限流。
5. 对找回密码和支付二次验证保留最高优先级队列。

## 恢复验证

- 短信发送 P95 小于 3 秒。
- 失败率小于 1%。
- 登录验证码请求转化率恢复正常。
- 供应商控制台无未处理错误码激增。

## 用户侧话术

如果用户反馈收不到验证码，请先提示等待 60 秒并重试；如果同一手机号 5 分钟内仍无法收到，转人工客服并记录手机号归属运营商。
