# 库存扣减失败率升高告警处理手册

## 告警名称

INVENTORY-DEDUCT-FAILURE-RATE-HIGH

## 适用范围

适用于库存锁定、扣减、释放链路异常。业务现象可能是用户下单提示库存不足、超卖保护触发、支付后订单无法进入履约。

## 告警触发条件

- 指标：`inventory_deduct_fail_total / inventory_deduct_total`
- 触发：失败率大于 2%，持续 5 分钟
- 严重级别：P1
- 关联服务：`inventory-service`、`order-service`、`promotion-service`

## 快速判断

1. 如果失败原因是 `INSUFFICIENT_STOCK`，先判断是否真实售罄。
2. 如果失败原因是 `LOCK_TIMEOUT`，优先排查 Redis 或数据库锁竞争。
3. 如果失败原因是 `SKU_NOT_FOUND`，排查商品主数据同步。
4. 如果失败集中在促销 SKU，排查活动限购和库存预占配置。

## 排查 SQL

```sql
select sku_id, count(*) as fail_count
from inventory_deduct_log
where created_at > now() - interval '15 minutes'
  and status = 'failed'
group by sku_id
order by fail_count desc
limit 20;
```

## 常见原因

- 秒杀活动未提前预热热点 SKU 库存缓存。
- 商品上下架状态与库存系统不同步。
- Redis 主从切换后锁 key 短暂不可用。
- 订单重试导致同一 request_id 重复扣减。
- 库存释放补偿任务延迟，导致可售库存长期偏低。

## 处置步骤

1. 对热点 SKU 开启库存本地缓存保护，限制每秒扣减请求。
2. 对异常 SKU 执行库存重算任务，核对真实库存、锁定库存、可售库存。
3. 如果是 Redis 锁故障，切换到数据库乐观锁兜底模式。
4. 如果发生超卖风险，暂停相关 SKU 售卖，并通知商品运营。
5. 对重复 request_id 的订单执行幂等修复，不允许手工直接修改库存数字。

## 恢复验证

- 扣减失败率低于 0.3% 并持续 10 分钟。
- 热点 SKU 可售库存与库存流水一致。
- 订单履约失败数不再增长。

## 业务通知模板

库存服务出现扣减异常，当前已执行限流与库存重算。受影响 SKU 已进入保护模式，预计 15 分钟内恢复。若发现超卖风险，将立即暂停售卖并补发用户通知。
